# File Inventory & Restructure Proposal

This documents what every file in the repo does, which ones are actually used at
runtime/build time, and a proposed reorganization. Generated 2026-11-09 from a live
local run (`python3 build-worker.py` → `node dev.mjs`).

## How to run locally

```bash
python3 build-worker.py      # regenerates worker/index.js from source
PORT=8787 node dev.mjs       # serves the worker locally (3000 may be taken)
```

## How it actually works

`worker/index.js` is a **generated** file (1.87 MB), produced by `build-worker.py`.
The generator reads the source files and inlines them, serving each one at a route:

| Route | Source file(s) |
|---|---|
| `/` | `page.html` |
| `/app.js` | `app.js` |
| `/journey.js` | `journey.js` + `batch-export.js` |
| `/holo.js` | `holo.js` |
| `/material-assets.js` | `card-identity.js` + `resource-coordinator.js` + `material-assets.js` + `discovery-buffer.js` |
| `/material-renderer.js` | `material-renderer.js` |
| `/recommender.js` | `recommender.js` (loaded as a Web Worker) |
| `/card-resources.js` | `card-resources.js` |
| `/catalog.json` | `catalog.json` |
| `/catalog-bundle.json` | `catalog.json` + manifest + alternatives + proxies |
| `/data/*.json` | `generated/card-resources/*.json` |
| (inline `MATERIALS`) | `materials.json` |
| `/api/session/*` | inline worker code + R2 `BUCKET` |

### Active build chain

```
scripts/build.sh
  └─ build-worker.py
       └─ scripts/build-card-resources.py   (reads data/, writes generated/)
  └─ scripts/validate-card-resources.py
  └─ node scripts/validate-catalog-artifact.mjs
dev.mjs                                     (local dev server)
```

## Issues found

1. **Generated files are committed** — `worker/index.js` (1.87 MB) and `generated/`
   are deterministic build outputs, yet tracked. Every `catalog.json` change makes a
   multi-MB diff.
2. **16 stale generated JSONs** — content-addressed artifacts accumulate in git.
3. **Stale `README.md`** — still the original starter boilerplate ("Edit
   `worker/index.js` directly", old `commands`); contradicts the real
   `build-worker.py` workflow.
4. **9 orphaned scripts + 11 orphaned data files** at the root / in `scripts/` / `data/`.
5. **45 tests, no runner** — `package.json` has only `"dev"`; nothing runs `*.test.*`.
6. **Flat repo root** — runtime modules, tests, and one-off scripts all mixed at the top level.

### Files to move

- **12 runtime files** → `src/`
- **9 one-off scripts** → `scripts/archive/` (and `build-worker.py` + `dev.mjs` → `scripts/`)
- **45 tests** → `tests/`
- **5 docs** → `docs/`
- **`catalog.json` + `materials.json`** → `data/`
- **11 orphaned data files** → `data/archive/`

### References to update

- `build-worker.py` — read `src/*` and `data/catalog.json`/`data/materials.json` instead of root paths.
- `scripts/build.sh` — `build-worker.py` path (and any moved script paths).
- `scripts/build-card-resources.py` — `catalog.json` → `data/catalog.json`.
- `scripts/validate-card-resources.py` + `scripts/validate-catalog-artifact.mjs` — `catalog.json` → `data/catalog.json`.
- Tests that read `data/card-metadata/*` and `catalog.json` — update relative paths.
- `dev.mjs` — `worker/index.js` path (unchanged if run from root).
- `package.json` — add a `test` script (e.g. `node --test tests/`) once tests are in `tests/`.
- `.gitignore` — optionally ignore `worker/index.js` and `generated/` (verify the hosting
  workflow doesn't require them committed before doing this).
